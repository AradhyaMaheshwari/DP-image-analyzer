01
PURPOSE

Image analysis, in one workspace.

CrackVision applies a trained YOLO segmentation model to a still surface image. It presents the source image and the generated mask-and-box overlay together, so a reviewer can inspect the prediction in context. This edition is dedicated to uploaded-image analysis; it does not access a Raspberry Pi, webcam, or live video feed.

02
USER INSTRUCTIONS

Run an image analysis.

  1. Choose a surface image. Select or drop a JPG, JPEG, or PNG file no larger than 4 MB. The preview shows the selected file and its dimensions.
  2. Start inference. Choose Analyze image. The backend loads the trained checkpoint on its first request and reuses the model for later analyses.
  3. Review the output. Compare the original with the generated segmentation masks and bounding boxes. Check the detection count, maximum confidence, processing duration, and image dimensions.
  4. Save what you need. Use the download link above either image. Select another image or clear the results to continue.
Image qualityGood focus, steady framing, and even lighting can make small surface features easier to review. Avoid treating an automated prediction as a final structural assessment.

06
INTERPRETATION

Read the model output carefully.

A detection means one or more predictions passed the configured confidence threshold. A zero-detection result means no prediction met that threshold for this image; it does not establish that the surface is crack-free. The displayed maximum confidence is the highest score among returned detections. Masks and boxes are model visualizations, not measurements of crack depth or structural safety.

Review reminderUse consistent image capture and qualified inspection judgment when making maintenance or safety decisions.
07
IMAGE HANDLING

Upload and output limits.

  • Accepted image formats: JPG, JPEG, and PNG.
  • Maximum upload size: 4 MB per request.
  • Output preview: scaled to a maximum edge of 1280 px and JPEG-compressed for transfer.
  • The backend does not save uploads or results to persistent project folders; the source preview uses the browser’s temporary object URL.
  • On serverless hosting, CPU inference time and cold starts depend on the host and its function limits.
08
TROUBLESHOOTING

Common checks.

The status says “Model missing.”

Confirm the trained best.pt checkpoint is included with the website project and that the configured model filename is correct.

The upload is rejected.

Use a valid JPG, JPEG, or PNG file under 4 MB. Re-export oversized images at a smaller resolution or JPEG quality.

The analysis fails to start.

Check the terminal or hosting function logs for missing Python packages, checkpoint loading errors, or memory/time limits.

No crack is detected.

Review image focus, lighting, and framing. Remember that a prediction must reach confidence 0.15 to be displayed; compare against a suitable inspection reference.
